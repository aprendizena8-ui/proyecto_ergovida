# AGENTS.md

## Repo layout (read this first)
- Flutter app lives at the repo root (`lib/`, `pubspec.yaml`, name `tarea`). This is the active app.
- `proyecto_ergovida/` is a stale, fully tracked duplicate of the app. Edit root `lib/`, never the nested copy.
- `backend/` contains two unrelated servers:
  - Spring Boot + JPA + MySQL: `backend/src/`, `pom.xml`, entry `BackendApplication.java`, port 8080.
  - Legacy/in-memory Node auth server: `backend/server.js`, `package.json`, tests in `backend/test/`, also port 8080.
- Root `app.py`, `Dockerfile`, `docker-compose.yml`, `nginx.conf`, `locustfile.py` are a separate Flask stub on port 5000. Docker Compose does **not** run the Spring backend or the Flutter app.
- `docs/implantacion/INFORME_RENDIMIENTO.md` documents the Flask/Docker load tests, not the Spring backend.

## Commands
Flutter (from repo root):
- `flutter pub get`
- `flutter run -d windows` (or `-d chrome`)
- `flutter analyze`
- `flutter test` (currently only a placeholder test, no real coverage)

Spring backend (from `backend/`):
- `.\mvnw.cmd spring-boot:run`
- `.\mvnw.cmd test` / `.\mvnw.cmd package`
- Requires MySQL at `localhost:3306/ergovida_db`, user `root`, empty password (`src/main/resources/application.properties`). `@SpringBootTest` also needs MySQL, so tests fail without it.

Node auth server (from `backend/`):
- `node server.js` or `npm start`
- `npm test` (node:test against `server.js` via `startServer(0)`; users are in-memory and reset on restart)

There is no CI or pre-commit config. Run the relevant checks manually.

## Backend/API gotchas
- Do not run the Node server and Spring Boot backend simultaneously: both bind 8080.
- They have incompatible auth contracts:
  - Flutter `AuthService` sends `{name,email,password}` to `http://127.0.0.1:8080`, expects `{success:true,...}` — matches `server.js`.
  - Spring `AuthController` expects `{nombre,correo,password}` and returns a `User`/`LoginResponse`, not `{success}`.
- Other Flutter services use `ApiClient` (base `/api`) against Spring CRUD routes: `/users`, `/ejercicios`, `/estadisticas`, `/horarios`, `/pausas-realizadas`, `/rutinas`, `/health`. `ErgoVida_Collection.json` is the Postman source of truth for these CRUD payloads.
- `ApiClient` switches Android emulator traffic to `10.0.2.2`, but `AuthService` hardcodes `127.0.0.1`, which breaks auth on Android emulators.
- Spring Security permits all `/api/**`; auth is not token-based despite the DTOs.

## Conventions
- UI copy and most backend model fields are Spanish (`nombre`, `correo`, `rol`, `activo`); keep that naming.
- State uses plain `StatefulWidget` + `ChangeNotifier`; no routing/state-management package. Theme lives in `lib/main.dart`.
- Lints come from `package:flutter_lints/flutter.yaml`; no custom rules.
- `windows/flutter/generated_*`, `linux/flutter/generated_*`, and `macos/Flutter/GeneratedPluginRegistrant.swift` are generated by `flutter pub get`; do not hand-edit.
- `assets/animations/` is declared in `pubspec.yaml` but only contains `.gitkeep`; add real files before referencing new assets.
- Ignore stray empty files `backend/auth` and `backend/csrf.disable())`.
